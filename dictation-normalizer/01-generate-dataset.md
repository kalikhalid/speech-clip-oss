# Промпт: генерация датасета

Для агента с доступом к файловой системе (sub-agent / Claude Code и т.п.).
Каждый агент СНАЧАЛА читает реальную историю распознавания, потом генерирует
данные в её стиле. Запускай несколько агентов / несколько раз, пока не
наберёшь 3–5к строк. Результат — таблица IN/OUT (→ экспорт в CSV/TSV).

---

```
# Шаг 0: изучи реальные ошибки моего ASR (ОБЯЗАТЕЛЬНО, до генерации)
Прочитай файл истории распознавания:
  ~/Library/Application Support/dev.speechclip.oss/history.json
Это JSON с массивом entries; в каждом элементе:
  - "raw_text"        = что выдал ASR (Parakeet), термины кириллицей по звучанию;
  - "normalized_text" = текст после пост-обработки (может быть кривым — НЕ эталон).
Также прочитай примеры реальных искажений:
  dictation-normalizer/data/parakeet-distortions.tsv  (колонки IN / OUT / NOTE).

Из этих файлов извлеки, КАК ИМЕННО мой ASR коверкает термины (ридми→ритми,
энв→Энф, гит→гид, слак→слаг, докер комполз, систем ситил и т.п.) и
ВОСПРОИЗВОДИ ровно такой стиль искажений в колонке IN. Не выдумывай
«идеальное» звучание — бери паттерны искажений из моей реальной истории.
normalized_text используй ТОЛЬКО как сигнал, какие термины встречаются;
правильный OUT определяй сам по правилам ниже.

# Шаг 1: сгенерируй данные
Создай таблицу с двумя колонками "IN" и "OUT", заполни её 50 строками
обучающих данных по правилам ниже.

# Контекст задачи
Программа распознаёт русскую речь и записывает иностранные слова и
тех-термины русскими буквами «как слышит» (коммит, мастер, карго томл,
джейсон, зум, эксель). Нужны данные, чтобы научить модель возвращать
таким словам правильное написание (commit, master, Cargo.toml, .json,
Zoom, Excel), НЕ трогая обычные русские слова.

# Что в колонках
- IN  = реплика, где иностранные слова/термины написаны русскими буквами
        по звучанию, а русские слова обычные.
- OUT = та же реплика, где термины записаны правильно (латиницей или
        как код/название), а все русские слова оставлены БЕЗ ИЗМЕНЕНИЙ.

# Железные правила
1. Русские глаголы, предлоги, союзы НИКОГДА не переводи на английский.
   «сделай коммит» → «сделай commit» (НЕ «make commit»).
2. Меняется ТОЛЬКО написание термина. Порядок слов сохраняется один в один.
3. ИМЕНА ФАЙЛОВ в OUT пиши через собачку @, БЕЗ форматирования как код.
   Примеры: ридми точка эм дэ → @README.md ; пакедж джейсон → @package.json ;
   карго томл → @Cargo.toml ; точка энв → @.env
   ВАЖНО: если Parakeet УЖЕ выдал имя файла латиницей в IN (clean_dataset.py,
   merge_dataset.py, config.yaml) — в OUT всё равно ставь @: @clean_dataset.py.
   Паттерн «который называется … .py» — обязательно включай в датасет.
4. Остальные термины (команды, бренды, сервисы) — обычной латиницей,
   без @ и без code-форматирования: commit, docker compose, Zoom, Figma.
5. Один и тот же термин в разных строках озвучивай ПО-РАЗНОМУ
   (commit → коммит / комит; remote → ремот / римоут; .json → джейсон / жсон).

# Фантазируй и бери слова из РАЗНЫХ сфер
Не ограничивайся программированием. Сам придумывай разнообразные реплики
из любых сфер, где в русской речи проскакивают иностранные слова:
- разработка: git, docker, файлы, сборка, тесты, деплой, сервисы;
- рабочие инструменты: Zoom, Slack, Notion, Figma, Excel, Google Docs, Jira;
- бренды и продукты: YouTube, iPhone, Windows, Photoshop, Telegram;
- аббревиатуры: API, URL, SQL, PDF, HR, KPI, AI;
- бытовые англицизмы и любые другие сферы — фантазируй свободно.
Выдумывай живые, естественные фразы, как реально говорят люди.

# КАК Parakeet реально коверкает звук (важно!)
ASR слышит не «чистое» звучание термина, а искажённое. Озвучивай термины
в IN так, как их РЕАЛЬНО коверкает распознавалка, а не идеально:
- глотает/меняет буквы: ридми→ритми, энв→Энф, гит→гид, слак→слаг, джейсон→джейсон/James;
- разбивает или склеивает слова: запушфорс, докер комполз, гид чекаут, систем ситил,
  лискрипт (от «отработал ли скрипт»), отработалли, запустилскрипт;
- путает похожие по звуку: ребейс→рейлс-подобное, чекаут→краул-подобное, каргот вместо карго тест;
- ставит заглавные и запятые рандомно: «Открой Карго, Томал».
Делай ~40% IN строк именно с такими «грязными» искажениями — модель должна
учиться чинить реальный вывод ASR, а не лабораторно-чистый.

# Пунктуация и регистр (как у реального ASR!)
Parakeet ставит точки, запятые и заглавные буквы — значит и в IN, и в OUT
они ДОЛЖНЫ быть, реалистично и иногда «криво» (лишняя запятая в середине
термина: «Открой Карго, Томал»; заглавная не к месту). Правило:
- IN  = с пунктуацией и заглавными, как реально выдаёт ASR.
- OUT = ТА ЖЕ пунктуация и регистр предложения сохраняются 1:1; меняется
        только написание самого термина. Точку в конце, запятые, заглавную
        первого слова НЕ удаляй и НЕ добавляй от себя.
Сделай ~70% строк с нормальной пунктуацией, ~30% «грязных» (рандомные
запятые/заглавные внутри терминов, как у ASR на длинной речи).

# Анти-галлюцинация (железно!)
Если звучание побито так, что термин угадать НЕЛЬЗЯ однозначно — оставляй
слово КАК ЕСТЬ, не выдумывай (НЕ «ребейс»→«Rails», НЕ «комител»→«Notebook»).
Лучше не тронуть, чем подставить неправильный термин. Добавь несколько строк,
где сомнительное/незнакомое слово в OUT остаётся без изменений.

# Состав 50 строк (соблюдай пропорции)
- 28 строк: обычные реплики с терминами из РАЗНЫХ сфер, 1–3 действия/мысли.
- 12 строк: ЧИСТАЯ русская речь без единого иностранного термина — IN и OUT
  ПОЛНОСТЬЮ одинаковые (бытовые и рабочие фразы, вопросы, болтовня).
- 6 строк: длинные склеенные цепочки из 4+ действий/мыслей подряд без
  знаков препинания, как будто человек говорит на одном дыхании.
- 4 строки: ловушки, где русское слово вплотную к термину
  (запушил в ремот → запушил в remote; скинул в зум → скинул в Zoom).

# Разнообразие
Меняй сферы, глаголы, длину, тон и порядок. Не повторяй однотипные фразы.

# Вывод
Только таблица с колонками IN и OUT, без пояснений до или после.
```
