# Промпт: проверка (QA) датасета

После генерации прогони собранные строки через этот промпт, чтобы
отловить плохие пары ПЕРЕД обучением. Мусорные данные = плохая модель.

Вставляй данные порциями (например, по 100–200 строк) в формате,
который у тебя есть (таблица / CSV / список «IN → OUT»).

---

```
Ты — строгий проверяющий (QA) обучающего датасета для модели,
которая исправляет русскую голосовую диктовку: меняет английские
тех-термины, записанные русскими буквами «как слышит» (коммит, карго томл),
на правильное написание (commit, Cargo.toml), НЕ трогая русские слова.

Я дам тебе пары IN → OUT. Проверь КАЖДУЮ пару по правилам ниже и найди
ошибочные. Не исправляй молча — сначала покажи отчёт.

# Правила корректной пары
1. OUT отличается от IN ТОЛЬКО написанием тех-терминов. Любое русское
   слово, порядок слов, смысл — без изменений.
2. Русские слова НЕ переведены на английский.
   Ошибка: «сделай коммит» → «make commit». Правильно: «сделай commit».
3. Термины в OUT записаны правильно и консистентно во всём наборе
   (везде @Cargo.toml, а не где-то "cargo toml"; везде Zoom, а не "zoom").
4. ИМЕНА ФАЙЛОВ в OUT — через собачку @ и БЕЗ code-форматирования:
   @README.md, @package.json, @Cargo.toml, @.env. Ошибка, если файл без @
   или обёрнут в code/обратные кавычки. Прочие термины — без @.
5. Если в IN нет тех-терминов — OUT обязан быть ПОЛНОСТЬЮ равен IN.
6. Нет дубликатов и почти-дубликатов (одна и та же фраза).
7. В IN термины правдоподобно «озвучены» по-русски (так реально слышит ASR),
   а не оставлены латиницей.

# Что проверить дополнительно
- Баланс: какая доля пар без изменений (IN==OUT)? Норма ~20–25%.
  Если сильно меньше — предупреди (риск over-correction).
- Разнообразие: есть ли длинные склеенные команды? Не однотипны ли фразы?

# Формат отчёта
1. Таблица проблемных пар: | № | IN | OUT | тип ошибки | как исправить |
   Типы ошибок: ПЕРЕВОД_РУССКОГО, ИЗМЕНЁН_СМЫСЛ, НЕКОНСИСТЕНТНЫЙ_ТЕРМИН,
   ФАЙЛ_БЕЗ_СОБАЧКИ, ДОЛЖНО_БЫТЬ_БЕЗ_ИЗМЕНЕНИЙ, ДУБЛИКАТ,
   ТЕРМИН_НЕ_ОЗВУЧЕН_В_IN, ПРОЧЕЕ.
2. Сводка: всего пар / проблемных / доля IN==IN / краткая оценка качества.
3. Список рекомендаций, что добавить или убрать.

Если все пары корректны — так и напиши и приведи только сводку.
```
