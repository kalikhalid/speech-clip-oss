# Анализ сырого Parakeet и стратегия нормализатора

> Основано на 290 реальных записях из `~/Library/Application Support/dev.speechclip.oss/history.json`.
> Анализируется **только `raw_text`** (выход ASR Parakeet TDT 0.6B v3). Качество выхода LLM
> игнорируется намеренно: в истории смешаны две разные downstream-модели
> (Gemma 3 270M ранее и Qwen 3.5 0.8B сейчас), поэтому выводы строятся на сыром ASR,
> который для всех записей одинаков.

## Природа сырого Parakeet: фонетически точная русская запись

Parakeet не «ошибается» — он честно записывает кириллицей то, что услышал. Английские
термины выходят как русская фонетика. Задача нормализатора не семантическая, а
**реконструкция намеренного токена**.

## Паттерн 1. Расширения файлов = `«точка» + фонетическое слово` (почти детерминировано)

Самый регулярный паттерн — 43 фразы из 290. После слова «точка» идёт расширение по звучанию:

| После «точка» | Частота | Расширение |
|---|---|---|
| эмди / эм / мди / мд / м ди | 18 | `.md` |
| пай | 7 | `.py` |
| джейсон / джисон | 8 | `.json` |
| рс / раст | 9 | `.rs` |
| тис | 1 | `.ts` |
| свелд | 1 | `.svelte` |

**Чинится таблицей фонетических ключей расширений** + правилом `точка <ext-слово> → .<ext>`.
LLM не нужна, детерминированно.

## Паттерн 2. Имя файла = шаблон `[файл] <корень> точка <ext>`

`файл Мэйн точка пай` → `main.py`. Слово-маркер «файл» (12+ фраз) почти всегда предшествует
имени файла. Это **структурный шаблон** для регулярки/FST: маркер «файл» включает режим сборки
имени, «точка» разделяет корень и расширение.

## Паттерн 3. Один термин → широкий фонетический разброс (главная сложность)

Parakeet пишет один термин по-разному в зависимости от произношения:

| Термин | Варианты Parakeet |
|---|---|
| **README** | реадми, редми, редьми, **рядми**, **ритми**, реал ми, реальми |
| **main** | мэйн, мейн, майн |
| **package** | пэкэдж, пэкеш, пакет |
| **cargo** | карго, каргот, **карагутом**, **карма том** |
| **git** | гид, гит |
| **commit** | комит, заком…, закам… |
| **json** | джейсон, джисон |

Edit-distance между `README` и `ритми` огромный — **фиксированный словарь это не покрывает**
(отсюда разбухший seed-словарь на 520 правил-заплаток). Нужен **фонетический ключ для кириллицы**:
`редми`, `рядми`, `ритми` дают близкий звуковой код и матчатся на один лексикон-токен `README`
по порогу. Один токен в лексиконе вместо 7 строк словаря.

## Паттерн 4. Дробление и запятые

- Термин разбит на 2 слова: `Реал Ми`, `М Ди`, `карма том` → склеивать соседние токены перед матчем.
- Parakeet вставляет запятые внутрь термина: `файл, Мэйн, точка Раст` (16 фраз).
  `sanitize_input` в `src-tauri/src/normalizer.rs:71` уже снимает запятые — правильно, но
  применяется только перед LLM; должно быть базовым шагом всего пайплайна.

## Ключевой факт для архитектуры: 59%+ — чистый русский

173 из 290 фраз не содержат тех-терминов («Откати последний релиз», «Нет ли уже обученных
моделей?»). Их **нельзя трогать вообще**. Правильная стратегия — не «переписать фразу», а
**найти островки тех-терминов и заменить точечно**, остальное оставить байт-в-байт.

## Рекомендуемый порядок обработки (всё до LLM, детерминированно)

1. **Нормализация разделителей:** снять запятые внутри тех-кластеров, схлопнуть пробелы
   (уже есть `sanitize_input`).
2. **FST расширений:** `точка <ext-слово> → .<ext>` по фонетической таблице. Самый частый и
   самый регулярный паттерн.
3. **Шаблон имени файла:** маркер «файл/скрипт» + корень + расширение → `main.py` / `@main.py`.
4. **Фонетический лексикон-матч для отдельных терминов** (cargo, docker, git, commit,
   README как самостоятельное слово): кириллический звуковой ключ + порог edit-distance по
   ключам, склейка соседних токенов. **Только по границам слов** — чистый русский не затрагивается.
5. **LLM (Qwen 0.8B) — только на остаток неоднозначности**, не на каждую фразу. На 59% чистого
   русского её можно не звать вовсе.

## Главный вывод

Сырой Parakeet — это **фонетически регулярный сигнал**, а не шум. Расширения и имена файлов
(самый частый кейс диктовки разработчика) ловятся почти на 100% детерминированной таблицей +
шаблоном. Фонетический ключ закрывает разброс вариантов одного термина. LLM остаётся для редких
контекстных случаев.

## Следующий шаг

Построить фонетическую таблицу расширений + лексикон корней прямо из `data/dataset.tsv` и этих
